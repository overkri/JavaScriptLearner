# Bug hunt — три бага в приложении

В этом задании не нужно писать новые функции: три готовых фрагмента приложения
содержат намеренные баги. Найдите их по симптомам, исправьте и добейтесь
зелёных тестов:

```bash
npx vitest run tests/m11/bughunt.test.js
```

Файлы с пометками `FIXME(11.x)` лежат в `src/playground/bugHunt/`. Эталоны —
в `solutions/src/playground/bugHunt/`.

---

## Баг 1. Мутация состояния

**Файл:** `src/playground/bugHunt/mutationBug.js`

**Симптом.** После добавления тега исходная задача тоже меняется. История
(undo/redo) не фиксирует изменение, React-подобный UI не перерисовывается:
ссылка на массив осталась прежней.

**Как воспроизвести.**

```js
const task = { id: 't1', title: 'Task', tags: ['work'] };
const updated = addTagToTask(task, 'home');
console.log(task.tags); // ожидалось ['work'], фактически ['work', 'home']
```

**Подсказка.** `push` меняет массив на месте. Нужны новый массив и новый объект.

**Критерий готовности.** Тест «adds a tag without mutating the original task»
зелёный; исходный `tags` не изменился.

## Баг 2. Потерянный `this`

**Файл:** `src/playground/bugHunt/lostThisBug.js`

**Симптом.** `counter.increment()` работает, а передача метода колбэком ломает
приложение:

```js
const { increment } = counter;
increment(); // TypeError: Cannot read properties of undefined (reading 'state')
```

**Как воспроизвести.** Откройте консоль браузера и выполните код выше. Или
запустите тест «keeps working when the method is detached».

**Подсказка.** Обычный метод получает `this` в момент вызова. При отрыве от
объекта `this` становится `undefined` (strict mode). Исправьте через замыкание,
стрелку или `bind`.

**Критерий готовности.** Тест «keeps working when the method is detached from the
object» зелёный; счётчик увеличивается при вызове отдельной функции.

## Баг 3. Гонка запросов

**Файл:** `src/playground/bugHunt/raceBug.js`

**Симптом.** Медленный ответ на старый поисковый запрос перезаписывает
результаты нового. Введите «ab», быстро сотрите до «a» — и увидите результаты
«ab».

**Как воспроизвести.** В тесте два запроса запускаются подряд, затем первым
резолвится новый, а старый — позже. Ожидается один вызов `onResult` с результатом
нового запроса.

**Подсказка.** Запоминайте номер запроса при старте и сравнивайте его с текущим
перед вызовом `onResult`. В реальном приложении дополнительно отменяйте
запрос через `AbortController` (модуль 7).

**Критерий готовности.** Тест «ignores a stale response that arrives after a
newer one» зелёный; `onResult` вызван ровно один раз с `['B'], 'b'`.
